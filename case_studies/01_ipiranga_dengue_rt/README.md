# Case study 01 — Ipiranga (PR) dengue Rt, 2025

Supplementary computational evidence for the GEI/EpidBot paper:
**weekly effective reproduction number (Rt) for dengue in Ipiranga, Paraná, Brazil, 2025.**

Corresponds to **Sections 4.3 (orchestration and adaptive repair)** and
**4.4 (provenance and traceability)**.

This directory contains artifacts **recovered from the original session** (datasets,
RO-Crates, the figure, the generating code) alongside **documentation, reproducibility
code and verification code written afterwards**. The categories are kept in separate
directories and labelled throughout. **Nothing in `artifacts/` was edited** — every file
is byte-identical to the copy that still exists in the original storage location, and
the digests are in `MANIFEST.csv`.

> **Read `provenance.md` first.** It grades every claim in the original answer against
> the stored evidence, across seven evidence tiers. It distinguishes what was *recovered*
> from what was *reported* in the chat, what has since been *reproduced* by re-execution,
> and what remains *unsupported*.

> **Correction notice (revision 2, 2026-11-25).** A verification pass has since
> re-executed the archived estimator on the archived data. As a result several claims
> that revision 1 graded narrative-only are now reproduced, **one narrative figure was
> found wrong** ("30/50 weeks" → **30/52**), and six inconsistencies were resolved. None
> of this was achieved by editing an original artifact; all corrections live in
> `verification/` and `provenance.md`. See `verification/inconsistencies.md`.

> **Licensing caveat.** The recovered RO-Crates carry **no licence field**, so the
> redistribution terms of the two Parquet files could not be verified. Read `NOTICE.md`
> before treating this directory as a public data release.

## 2. What the investigation did (as reconstructable from artifacts)

1. Pulled InfoDengue weekly dengue counts for Ipiranga (`municipio_geocodigo = 4110508`)
   from Mosqlimate, window `2024-12-01 → 2026-01-15` (59 epi-weeks, SE 202449–202602).
2. Derived `ipiranga_weekly_2025.parquet` (57 rows, SE 202449–202553) and
   `ipiranga_biweekly_2025.parquet` (29 two-week rows; case total 140 in both).
   Verified at packaging time: the weekly file is exactly the 59-row dataset truncated to
   `SE <= 202553`, and the biweekly file is exactly its 14-day aggregation.
3. Produced two `rt_estimate_*.webp` figures whose generating tool is **not recorded**.
4. Pulled a **second, deeper** InfoDengue window `2023-12-01 → 2025-12-28`
   (109 rows, SE 202349–202553).
5. Ran the custom sandbox script (snippet 15649) on that deeper dataset and wrote
   `ipiranga_rt_2025.png` (plot 2735): Cori et al. (2013) sliding-window Rt,
   7-week window, `Gamma(1, 0.2)` posterior prior, gamma serial interval discretised at
   `mean = 2.0` weekly periods, `sd = 1.0` (i.e. 14 d / 7 d), incidence per 100,000
   against a hard-coded population of 14,230.

That step 4 precedes step 5 is visible in file timestamps only. **Why** the deeper pull
was made is inference, not record — see `provenance.md` §6. The verification pass did not
and could not resolve this: re-running an analysis cannot recover a motive. This case
study therefore does **not** demonstrate "adaptive execution"; it documents an observed
re-retrieval of unknown motivation.

## 3. Reproducing

```bash
cd case_studies/01_ipiranga_dengue_rt
pip install -r reproducibility/requirements.txt

python reproducibility/reproduce_rt.py \
    --dataset artifacts/data/ds_2023-12-01_2025-12-28/data.parquet \
    --outdir ./out
```

`reproduce_rt.py` re-implements the archived estimator with portable paths and explicit
CLI parameters. It is **new code**, written for this archive; it is *not* the original
artifact. The authoritative script is `artifacts/code/snippet_15649__plot_2735.py`, which
contains absolute `/data/...` paths and writes directly to `/data/plots/`.

**Execution history.** At packaging time (revision 1) this script was written but *not*
executed, so that fresh output could not be confused with the original run. During the
verification pass (revision 2) it **was** executed, and its outputs are archived under
`verification/outputs/`. Its numbers agree with a re-execution of the archived estimator
to floating-point precision (max |ΔRt| = 1.78 × 10⁻¹⁵). **Both sets are new**; neither is
the original run's output.

Requirements now include **pyarrow** (the Parquet engine), which was missing from
revision 1 and without which `read_parquet` fails.

## 4. Verification (revision 2)

Full detail in `verification/verification.md`. Headline:

| Check | Result |
|---|---|
| Archived estimator re-run on archived data | reproduces 137 cases, 962.8/100k, max Rt 11.1061 at SE202540, latest 0.5362 [0.1741, 1.0983] |
| Rewrite vs archived estimator, 52 weeks | max \|ΔRt\| = **1.78 × 10⁻¹⁵** |
| Rewrite figure vs archived PNG | data geometry pixel-identical; differences confined to title rows 30–42 and 54–72 of 900 (subtitle string was rewritten) |
| Prior sensitivity, 8 priors | SE202539 spans 2.00–20.00; SE202540 spans 4.48–13.63 |
| Peak-week robustness | maximum moves to SE202539 under Gamma(1,0.1) and under SI 1.5/0.7 |
| "Latest Rt < 1" robustness | point estimate < 1 under all 8 priors; 95 % CrI excludes 1 under only 1 of 8 |
| Calendar vs epi-year filter | archived filter drops SE202501 (2024-12-29); 52 vs 53 weeks; cases unchanged |

### Six corrections

1. **"4 to 20" sensitivity range** belongs to **SE202539**, not to the week with the
   11.11 estimate (**SE202540**). Different week, different quantity.
2. **SE202541 has 7 window cases**, not 12 (12 is SE202542).
3. **"30/50 weeks" → 30/52.** Numerator right, denominator wrong.
4. **Zero-case counts:** 23 weeks with `casos = 0`; **9** zero-case *windows*
   (SE202530–SE202538), during which Rt drifts to the prior mean of 5.0 and is
   uninterpretable.
5. **Calendar-year filtering** on `data_iniSE` excludes SE202501; the analysis is 52
   weeks, not 53.
6. **"95% CI" → "95% credible interval"**: these are gamma posterior quantiles, not
   confidence intervals. The archived figure title repeats the error; the artifact is
   preserved as-is and must not be edited.

## 6. Data, licensing and redistribution

* **Upstream source**: InfoDengue / Mosqlimate (`api.mosqlimate.org`), municipality-level
  weekly dengue aggregates for Ipiranga, Paraná.
* **Granularity**: municipality-week counts. No patient-level records, no identifiers, no
  personal data — neither LGPD nor GDPR is implicated by these files.
* **Licence**: the recovered RO-Crates carry **no licence field, no creator and no
  publisher**. Redistribution is therefore governed by the upstream InfoDengue /
  Mosqlimate terms of use, which this archive does **not** restate and which were **not
  verified** during the verification pass. **See `NOTICE.md`** — a NOTICE does not create
  permission. Recommended default before public release: replace the two Parquets with a
  retrieval script plus checksums, or confirm the upstream terms and record them.
* **No credentials**: no API keys, tokens, cookies, `.env`, `config.db`,
  `chat_history.duckdb` or `private/` data is included. A pattern scan for
  `api_key|token|secret|password|bearer|authorization` plus GitHub/AWS/Slack/OpenAI key
  formats, private-key blocks, e-mail addresses and personal absolute paths over every
  file in this directory returned **no hits** (re-run at revision 2).

## 8. Known limitations

1. **The original execution chain is partly lost.** No tool-call log and no task plan
   survive; the transcript in `documentation/` is conversation-derived and **truncated**
   (marked `[CUT]`). See the warning box at the top of that file.
2. **The original run's numeric output was never archived.** Rt values are now
   *reproduced* from the archived code and data, not *recovered* from the original run.
   Agreement is corroboration, not recovery. See `provenance.md` §3 for the distinction.
3. **Snippet 15649's payload is a substitution** (see the caveat in §1).
4. **The two `.webp` files are unattributed** — the tool and parameters are unrecorded,
   and the numeric output of that tool comparison was never saved.
5. **The RO-Crate descriptions are factually wrong** ("for 2023" / "for 2024" while the
   data cover 2023-12-01→2025-12-28 and 2024-12-01→2026-01-15), and they carry no licence.
   The files were not corrected, to preserve originality. See `NOTICE.md` and
   `provenance.md` §7.
6. **The peak-week result is prior-dependent.** The maximum is SE202540 under the archived
   prior and under 7 of 8 tested priors, but moves to **SE202539** under Gamma(1, 0.1)
   (prior mean 10) and under a serial interval of 1.5/0.7 weeks. Report it with its
   specification attached.
7. **"Declining" at the end of 2025 is not statistically robust.** The point estimate is
   below 1 throughout (0.468–0.889 across priors) but the 95 % credible interval includes
   1 under 7 of 8 priors.
8. **"Adaptive execution" is not demonstrated.** The second retrieval is timestamped but
   its motivation is unrecorded. Do not claim adaptivity from this case study.
